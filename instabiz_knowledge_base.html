2.2 Creating a Quotation

  1. Go to Workspace → Sales & CRM → Quotation or press Alt+Q.
  2. Select Quotation To: choose Customer (existing) or Lead (prospect).
  3. Set Location: Maharashtra / Gujarat / Chennai. This auto-sets the company address, GSTIN, and document naming prefix.
  4. Add items. For each item row:
    • Enter Item Code (multi-token search available).
    • Enter dimensions: Width (mm), Length (mtr), Qty/Pkg, Total Pkg.
    • Qty is auto-calculated: for SQMT items: (width_mm / 1000) × length_mtr × qty_pkg × total_pkg; for others: qty_pkg × total_pkg.
    • Enter Rate. Amount is auto-calculated.
  5. The system automatically selects the GST template (In-state / Out-state) based on customer GSTIN vs company GSTIN.
  6. Floor Price check: if rate is below cost + minimum margin, Sales User is blocked; Sales Manager sees a warning.
  7. Save (Draft) then Submit.
Quotations have a valid_till date (auto-set to 1 month). A daily scheduler sends expiry warnings at 15, 7, and 1 day before expiry. Expired quotations are auto-closed.

2.3 Converting Quotation to Sales Order

  1. Open a submitted Quotation.
  2. Click Make → Sales Order (the custom mapper fires, carrying all dimensions, transport, address fields).
  3. Review the SO. Optionally add a Cancellation Reason field (required to cancel later).
  4. Submit the SO. Stock is reserved at this point.
SO submit is blocked if: (a) customer outstanding > credit limit AND oldest unpaid invoice is older than allowed days; OR (b) customer has 30+ day overdue invoices (custom_overdue_block flag set).

2.4 Creating a Delivery Note

  1. Open the submitted Sales Order.
  2. Click Make → Delivery Note.
  3. The DN inherits warehouse from location, transporter details, and all item dimensions.
  4. Set LR Number (custom_lr_number) and Transporter.
  5. Before submit, the system checks actual stock. If any item is short, a draft Stock Reconciliation is automatically created — submit it first, then re-submit the DN.
  6. On submit: E-Way Bill is auto-generated (if GST API is enabled), sales person gets a bell notification, and the stock update is broadcast to Live Stock Dashboard.

2.5 Creating a Sales Invoice

  1. Open the submitted Delivery Note.
  2. Click Make → Sales Invoice.
  3. The SI inherits the same DN number (e.g., DN IB-BWD-DC-00005 → SI IB-BWD-INV-00005).
  4. Optional: Enter Transport Charges (custom_transport_charges) — the system automatically adds proportional GST on transport to each GST row.
  5. On submit: E-Invoice (IRN) is auto-generated; Payment Entry can auto-reconcile.
If SI is created standalone (not from DN), it gets its own number from the global counter.

2.8 Reopening a Cancelled Document

Cancelled Quotations and Sales Orders can be reopened (not available for DN and SI once submitted):

  1. Open the cancelled document.
  2. Click Reopen button (visible on cancelled docs).
  3. The system resets docstatus to 0 (Draft) and adds an audit comment.
  4. For SO reopen: blocked if any submitted DN or SI is still linked.

2.9 Floor Price Enforcement

Each item can have a Minimum Margin % (custom_min_margin_pct) configured on the Item master. The floor price = valuation_rate × (1 + min_margin/100).

  • Sales User: Save is blocked if any row is below floor price.
  • Sales Manager / System Manager: Warning shown but save is allowed.

2.10 Margin % on Quotation Items

Each Quotation Item shows Margin % (custom_margin_pct), auto-calculated as:
margin % = (rate - valuation_rate) / rate × 100
This field is read-only and updates automatically when rate changes.

3. Payments, Advances & Credit Limits

3.1 Recording a Payment Against a Sales Invoice

  1. Open the submitted Sales Invoice.
  2. Click Make → Payment Entry.
  3. Set Amount Received, Payment Mode (Bank / Cash), and Reference No (cheque/NEFT number).
  4. Save and Submit.
Payment Entry on submit automatically sends a bell notification to all Accounts User, Accounts Manager, and System Manager roles.

3.2 Auto-Reconciliation of Payments

When a Payment Entry (Receive type) is submitted with no reference rows, the system automatically links it to the oldest outstanding Sales Invoices for that customer (FIFO order) until the payment amount is exhausted.

If the payment amount exceeds all outstanding invoices, the excess stays unallocated with an orange warning. Reconcile manually in Accounts → Bank Reconciliation.

3.3 Recording an Advance Payment Against a Sales Order

To record an advance (before invoice is raised):

  1. Go to Accounts → Payment Entry → New.
  2. Set Payment Type = Receive, Party Type = Customer.
  3. In the Payment References table, add a row:
    • Reference DocType: Sales Order
    • Reference Name: the SO number (e.g., IB-BWD-SO-00012)
    • Allocated Amount: the advance amount
  4. Save and Submit.
  5. The SO will now show Advance Received (custom_advance_paid) field updated automatically.

3.4 Attaching Advance Payment Screenshot / Document to Sales Order

To attach proof of advance payment (bank screenshot, WhatsApp screenshot, etc.):

  1. Open the Sales Order.
  2. Click the Attachment icon (paperclip icon at top-right of the form, or the Attachments section at the bottom).
  3. Click Add Attachment → Upload File.
  4. Select the image or PDF from your computer and upload.
  5. Alternatively, drag-and-drop the file onto the attachment area.
  6. The file appears in the Attachments section and is stored in Frappe's file system.
You can also attach files to any other document (Quotation, Invoice, Lead, etc.) using the same method. Attachments are visible to all users who have access to that document.

3.5 PDC (Post-Dated Cheque) Tracking

Use the IB PDC doctype to track post-dated cheques from customers:

  1. Go to IB PDC → New.
  2. Fill in: Customer, Cheque No, Cheque Date, Amount, Bank Name, Related Sales Invoice (optional).
  3. Status: Pending → Presented → Cleared / Bounced.
  4. The system sends a bell notification to Accounts roles 3 days before the cheque date.

3.6 Credit Limit Configuration

Set customer-level credit limit in Customer → Credit Limit tab:

  • Credit Limit: Maximum outstanding allowed (₹).
  • Bypass Credit Limit Check: Tick to skip enforcement for this customer.
  • Custom Days: Number of days an invoice can be overdue before blocking.

SO submit is blocked only when BOTH conditions are true simultaneously: outstanding > credit_limit AND oldest unpaid invoice older than custom_days.

3.7 Overdue Block

When a customer has a Sales Invoice overdue by 30+ days:

  • Daily scheduler sets custom_overdue_block=1 on the Customer.
  • New SO submit is hard-blocked for Sales Users; Sales Manager gets a warning only.
  • Block is automatically cleared when all overdue invoices are paid via Payment Entry.

4. Credit Notes, Debit Notes & Returns

4.1 Sales Return / Credit Note

A Credit Note is a Sales Invoice with is_return = 1. Use it when goods are returned by the customer.

  1. Open the original submitted Sales Invoice.
  2. Click Make → Return / Credit Note.
  3. The system creates a return SI with negative quantities.
  4. Fill in Return Reason (custom_return_reason) — this appears in the Credit Note Register report.
  5. Submit the Credit Note. It auto-adjusts the outstanding on the original invoice.
Credit Notes get their own naming series: IB-{LOC}-CN-##### (separate from INV sequence).

4.2 Delivery Return (Stock Return)

  1. Open the submitted Delivery Note.
  2. Click Make → Return.
  3. The return DN brings stock back into the warehouse.
  4. Create a Credit Note against the original SI separately (or from the return DN).

4.3 Purchase Debit Note

A Debit Note is a Purchase Invoice with is_return = 1. Use it when returning goods to a supplier.

  1. Open the original submitted Purchase Invoice.
  2. Click Make → Return / Debit Note.
  3. Naming: IB-{LOC}-DN-##### (the DN- prefix in purchase returns).
  4. Submit to update supplier outstanding.

4.4 Credit Note Register Report

Go to Reports → IB Credit Note Register to see all credit notes with return reasons, original invoices, and values. Filter by date range, customer, territory, or sales person.

4.5 General Ledger & Accounting Impact

All submitted Sales Invoices, Credit Notes, and Payment Entries create GL Entries automatically:

  • SI submit: Debit Customer AR account, Credit Sales Revenue account + GST accounts.
  • Credit Note submit: Reverses the above (Debit Sales Returns, Credit Customer AR).
  • Payment Entry: Debit Bank/Cash account, Credit Customer AR account.

View GL entries: Accounts → General Ledger report, or open any document → View → Ledger.

  1. Go to Workspace → Sales & CRM → Leads Pipeline or CRM → Lead → New.
  2. Fill in: Lead Name, Mobile No, Email, Territory.
  3. Enter Pincode (custom_pincode) — the system auto-fills City and District via India Post API.
  4. Save. The lead is automatically assigned to a sales person via round-robin within the Lead Sales Team for that territory.

5.3 Changing Lead Status (Quick)

In the Lead List view, click the coloured status pill next to a lead row to open a floating status picker — change status without opening the full form.

5.4 Logging Activity on a Lead

  1. Open a Lead.
  2. Click Log Activity button (top of form).
  3. Select Activity Type: Call / Meeting / WhatsApp / Email / Visit.
  4. Select Outcome: Positive / Neutral / Negative / No Answer.
  5. Add Notes and optionally set Next Follow-Up Date.
  6. Click Save. An activity entry appears in the Lead's timeline.

5.5 Lead Scoring

Each lead gets an automatic score (0–100):

  • Temperature: Cold=0, Warm=30, Hot=60 points.
  • Status bonus: up to 30 additional points.
  • Contact completeness: mobile/email/product interest/follow-up date present.

Score is visible as custom_lead_score on the Lead form.

5.6 Converting Lead to Customer

  1. Open the Lead (status should be Quoted or Hot).
  2. Click Make → Customer.
  3. The custom mapper carries: Territory, Pincode, City, District, Sales Person.
  4. A new Customer record is created linked to this Lead.

5.7 Win-Back Nudges (Automatic)

Daily scheduler triggers alerts:

  • Open/Replied Quotations with no activity in 14+ days → alert sent to rep.
  • Leads in Cold/Contacted/Warm status with no activity in 30+ days → alert to lead owner.

5.8 Lead Sales Team Configuration

Go to Lead Sales Team doctype to configure round-robin assignment:

  • Add Members (Users) and their Territories.
  • Leads from matching territories are assigned in round-robin order.
  • The team leader gets the Sales Manager role automatically on save.

9.2 E-Invoice (IRN) Auto-Generation

On Sales Invoice submit, IRN is generated automatically if:

  • Customer has a GSTIN (B2C invoices are skipped).
  • Invoice is not a return (credit notes skipped).
  • Invoice is not already IRN-stamped.

On failure: a warning is shown but the SI is not blocked. Check the Error Log for details.

The IB Tax Invoice print format (feature 70) automatically renders the IRN QR code on Page 1 when an IRN exists.

9.3 E-Way Bill Auto-Generation

On Delivery Note submit, an E-Way Bill is auto-generated if GST API is enabled. The system:

  • Maps custom_lr_number → lr_no (Lorry Receipt number).
  • Maps IB Transport GSTIN → gst_transporter_id.
  • Sets Dispatch From address = warehouse address per location mapping.
To generate E-Way Bill manually from DN list: select the DN → Actions → Generate E-Way Bill. An extended dialog lets you choose Transaction Type (Regular, Bill To-Ship To, Bill From-Dispatch From, Combination) and enter address overrides.

  1. Go to GST India → GSTR-1 Beta.

12.5 Payroll Processing

  1. Ensure each employee has a Salary Structure Assignment with the correct salary structure and effective date.
  2. PF opt-in: set provident_fund_account on Employee (blank = PF skipped).
  3. ESIC opt-in: set health_insurance_no on Employee (blank = ESIC skipped; also auto-skipped if base > ₹21,000).
  4. Run Payroll from HRMS → Payroll → Process Payroll. Select month, company.
  5. Salary slips are generated. The system credits 2 days leave (for IB Payroll) if employee has absences.
  6. Submit all salary slips, then post the payment journal entry.

12.6 IB Payroll Summary Report

12.7 Employee Exit & Full & Final Settlement

When an employee's relieving_date is set (status can be Active or Left at the time — both orders work):

  • On/after relieving day: System creates an Employee Exit Handover doc listing all pending Q/SO/DN/SI under that rep's name, and HR Managers get a bell notification. HR reassigns the pending documents.
  • Day after relieving: User account is disabled automatically.
Fixed 2026-07-02: the handover job previously required an exact relieving_date = today match plus status = Active; since HR commonly sets status to Left at the same time they enter a (often backdated) relieving_date, this silently skipped the handover for most real exits. The job now scans relieving_date ≤ today with no status filter, matching the retry-safe pattern already used by the account-disable job.

IB Full Final Settlement doctype auto-computes:

  • Years of Service, Gratuity (≥5 years: basic/26 × 15 × years), Leave Encashment, Total Payable.

17.3 Rate Contracts (Pricing Rules)

Rate contracts use native ERPNext Pricing Rules (no custom code). To set a rate contract for a customer:

  1. Go to Accounts → Pricing Rule → New.
  2. Set: Applicable For = Customer, Apply On = Item Code, Price or Discount = Rate.
  3. Set valid_from and valid_upto for the contract period.
  4. On Quotation/SO, the rate auto-applies when the customer + item combo matches.
Q→SO mapper copies rate from Q row. If contract rate changes after Q submission, SO carries the old rate — correct manually if needed.

19.4 Raven — Internal Team Chat

Raven (installed 2026-07-02) is a separate internal team chat app for Instabiz staff — distinct from the customer-facing WhatsApp integration above. Direct messages, channels, and file sharing between colleagues.

  • Open from the app switcher (top-left grid icon) or go directly to /raven.

  • Direct Messages — click a colleague's name in the People list to start a 1:1 chat.

If a user can't see other people in Raven, it is almost always because they haven't been added to the Raven workspace / General channel yet — this can happen for users on a Role Profile (Sales, Sales Manager, HR Manager), since Frappe re-syncs roles to the profile on every save and can silently strip a role added only to the individual user. Contact a System Manager.

20.2 Data Isolation (Sales Documents)

Non-privileged users (Sales User role without Sales Manager or System Manager) see:

  • Documents where custom_sales_person_user = their email, OR
  • Documents they created (owner = their email) where custom_sales_person_user is not set.

Privileged users (Sales Manager, System Manager) see all documents.

20.3 Customer Visibility for Sales Users

Sales Users see customers that are:

  • Permanently assigned to them (custom_sales_person_user = me), OR
  • Owned by them and unassigned (legacy docs), OR
  • Shared with them via IB Customer Share, OR
  • In their daily board (IB Customer Assignment, last 90 days) — only for unowned customers, OR
  • In their Lead Sales Team territories — only for unowned customers.
